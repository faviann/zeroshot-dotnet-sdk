# Migrating from 0.2 to 10.10.0.1-preview.1

`10.10.0.1-preview.1` follows `0.2.0-preview.1` and binds the same native release, 10.10.0.
It is the first preview of `10.10.0.1`. Later `10.10.0.1` previews may add breaking changes
to this file before `10.10.0.1` ships; after that, revisions of 10.10.0 cannot break.

## Contract types cannot be derived outside the SDK

Every abstract contract record now has a `private protected` constructor: `NativeContract`
and its grouping bases, and every tagged union base such as `TerminalResult`, `RunStatus`,
`HostedRunStatus`, `HistoryEvent`, `AgentAttachEvent`, `WatchEvent` and the dashboard
unions. Code that derived its own record from one of them no longer compiles.

Such a record never round-tripped: the serializer only produces and accepts the variants
native defines. Model your own data in a separate type, and convert at the boundary. Code
that only switches over the SDK's variants is unaffected, and its `default` arm can now
treat any other value as unreachable.

## `NativeHttpException` has one `Problem`

`NativeHttpException.Problem` is now a `NativeHttpProblem?`: one closed variant per
refusal shape, with the shared code on `Problem.Code`. `UiProblem`, `HistoryProblem` and
`DeviceTokenError` are removed, and `Problem` no longer has the type `TargetHttpProblem`.
Which variant you get depends on the operation:

| Operation | Variant | Facts |
| --- | --- | --- |
| Target and host-owned APIs | `NativeTargetProblem` | `Body`: the `TargetHttpProblem` |
| UI-routed dashboard routes | `NativeUiProblem` | `Body`: the `UiProblem` |
| Run history, in either dialect | `NativeRunHistoryProblem` | `Category`, `Message`, `Details` |
| OAuth device-token exchange | `NativeDeviceTokenProblem` | `Error` |

A malformed or unrecognized body still leaves `Problem` null with the status kept.
Default exception formatting still omits every remote fact.

| Before | After |
| --- | --- |
| `error.Problem?.Code`, `error.UiProblem?.Code` | `error.Problem?.Code` |
| `error.Problem!.Message`, `error.Problem!.Details` | `error.Problem is NativeTargetProblem { Body: var body }`, then `body.Message`, `body.Details` |
| `error.UiProblem!.Message` | `error.Problem is NativeUiProblem { Body: var body }`, then `body.Message` |
| `{ UiProblem.Code: "profile_conflict" }` | `{ Problem: NativeUiProblem { Code: "profile_conflict" } }` |
| `{ HistoryProblem: RunHistoryProblemCode.RunNotFound }` | `{ Problem: NativeRunHistoryProblem { Category: RunHistoryProblemCode.RunNotFound } }` |
| `{ DeviceTokenError: DeviceTokenError.SlowDown }` | `{ Problem: NativeDeviceTokenProblem { Error: DeviceTokenError.SlowDown } }` |

A history operation's refusal used to land on `Problem` (hosted, private exports) or
`UiProblem` (direct UI mount) beside `HistoryProblem`. It is now always a
`NativeRunHistoryProblem`, so code that matched `NativeTargetProblem` or
`NativeUiProblem` for a history read does not match. Read `Category`, or `Code` for an
unknown history code.
